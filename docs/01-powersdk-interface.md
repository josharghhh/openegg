## 0. How the app is wired (read this first)

* **Facades.** The app never calls `JniNatives` directly. All calls go through four singletons that are 1:1 pass-throughs: `powersdk/sdk/PowerSDK.java` (flight/camera/gimbal/params/Ray), `PowerSDKCamera.java` (Amba/PowerRay camera session + file ops), `PowerSDKBaseStation.java` (PVLink RF + AP Wi-Fi), `PowerSDKMount.java` (payload mount API). Callbacks are dispatched by `JniNatives.*Notify` to listeners held in the same singletons (`get...Listener()`); each has a single listener slot except `remoteControlParamNotify`, which iterates a `List`.
* **Connection state machine** lives in `powersdk/PVSdk.java` (class `Conn`): state 0 INIT: `initSDK(ip, port)` -> `initRayUuid(Build.SERIAL+Build.SERIAL)` -> `setRayBaseStationAddress("192.168.1.11", 8080)` -> `registerCallback()` -> `setConnectionListener(this)`; retry every 3.1 s. State 1: `connect()` (retry 3.1 s). `connectionNotify(1)` onConnectSuccess -> state 3: `connectDrone()` (retry 3.1 s). `connectionNotify(9)` onDroneConnected (or 6/7 RC type) -> state 4 DONE. `connectionNotify(5)` heartbeat timeout -> full reconnect after 10 s. `unInitSDK()` = `disConnectDrone(); disConnect(); unInitSDK()`.
* **Endpoints** (gcs/config/GlobalConfig.java): PowerEgg `initSDK("192.168.1.12", 20002)` (`DEFAULT_TCP_SERVER_IP`) from ui/fgt/fly/FlyFragment.java:974, or `"192.168.1.11"` (`DEFAULT_REMOTE_IP`) :20002 from FlyFragment.java:1413 / FlyControlFragment.java:187,200. PowerRay: 192.168.1.104:8080. Sonar: 192.168.1.1:20002/20001. Camera video for the Egg is NOT in this SDK (separate `vfsdk` / FFmpeg player).
* **Live PowerEgg UI path:** FlyFragment (connect, activation, version checks) -> OneselfCheckActivity (pre-flight self-check) -> **PVFlightControllerActivity** (flight screen: VFCameraManager, CustomGestureView gimbal, Google/Gaode map controllers extending BaseMapController, PowerManager, AircraftBatteryManager, TitleView/TopMenuView) + Egg*/Fly* settings fragments, CompassCalDFragment, ControlCalibrationFragment, EXPSettingsFragment.
* **Dead code** (never instantiated/started anywhere in the app): `ui/aty/fly/FlyControllerActivity.java` (older flight screen, contains the only `setMode()` and `startWayPoints` dialog flow), `ui/controller/VideoViewController.java`, `AmbaVideoViewController.java`, `FlyViewController.java`, `powersdk/manage/ConnectManager.java`, and `gcs/sdk/PVStationManager.java` (the only user of the whole RF/AP base-station API). Calls found only there are tagged MAYBE.
* **Tags.** USED = called (native) or listener registered (callback) from a live PowerEgg path - one call site cited. MAYBE = only in dead code, only generic, or no call site but plausibly needed for PowerEgg. OTHER-PRODUCT = only PowerRay / Dolphin / boat / sonar / PowerEye / mount API paths. File classification is by file/dir name (Ray*, Ship*, Water*, *Sonar*, *Eye*, Dolphin*, W4*, ship/, water/, pvsonar/ => other product).
* **Not called at all by the app:** `arm`, `disArm`, `takeOff`, `land`, `setHome`, `getHome`, `setFence`, `getFence`, `setGimbalMode`, `getSDKVersion`. PowerEgg arming/takeoff/landing is done from the RC; the app only does RTH (`rtl`), cancel (`backToLastMode`), waypoints, circle, follow-me, set-return-point and the safe area. A rebuild should still implement takeoff/land via MAVLink, but it has no app precedent for codes/semantics.

### 2f. Notes on telemetry callbacks and the alarm bitmask

* **Notify-then-poll.** Most telemetry callbacks carry only a status int (0 = new data); the listener then calls a native getter which returns a freshly built struct: `positionChangedNotify(0)` -> `getGlobalPositionIntParam()` (lat/lon int 1e7, see gcs/manager/PowerManager.java:263); `gpsRawIntNotify(0)` -> `getGpsRawIntParam()` (satellites_visible, fix_type); `attitudeAndGroundspeedChangedNotify(0)` -> `getAttitude()` + `getVfrHudParam()` (heading, speeds, alt) + `isArmed()`; `sysStatusNotify(0)` -> `getSystemStatusParam()` (battery). These map 1:1 onto MAVLink GLOBAL_POSITION_INT, GPS_RAW_INT, ATTITUDE, VFR_HUD, SYS_STATUS. ## 3. Param / model classes crossing the JNI boundary

## 4. Pure-Java logic over parameters, and every parameter name

### 4.1 Java-side logic worth replicating

* **Parameter values are int bit-patterns in a float.** The native API is `setParameter(String id, float v)` / `float getParameter(String id)` (cached value) / `requestParameter(String id)` (async fetch; result via one of the `*ParamNotify(status, paramId)` callbacks, status 0 set-ok, 1 set-timeout, 2 get-ok, 3 get-timeout). Almost every caller uses `Float.intBitsToFloat(intValue)` to write and `Float.floatToIntBits / floatToRawIntBits(getParameter(id))` to read, i.e. this mirrors MAVLink `PARAM_SET`/`PARAM_VALUE` with `MAV_PARAM_TYPE_INT32` carried bytewise in the float field. A few writers send real floats (`PV_GIM_ROLL_ADJ`, `PV_RC_*_EXP`, `RC_TRAN_USED` 0.0/1.0, `PV_GIM_AUTO_CAL` 0.0, `PV_RC_MODE`, `PV_CAM_SET_T*`).
* **Which callback carries a param ack** is decided natively (by param-id family, apparently): `paramSetGetNotify` (generic, `ParamGetSetManager`), `gimbalParamNotify` (PV_GIM_*), `cameraParamNotify` (PV_CAM_*), `remoteControlParamNotify` (PV_RC_*, multi-listener), `selfCheckNotify` (self-check list). The Java side switches on `paramId` strings in each listener.
* **`PowerSDK.activate(float v)`** (sdk/PowerSDK.java): sets static `JniNatives.activateFlagPowerSDK = true`, calls `setParameter("PV_V_KEY_FLAG", v)`, and arms a 2 s Timer that clears the flag. `sysDoNotify(4)` (set-key success) is only forwarded to the listener while that flag is true; `sysDoNotify(5)` clears it. Called as `activate(Float.intBitsToFloat(1))` in a loop (max 10 sends, 260 ms apart) from ui/fgt/fly/FlyFragment.java:1246 and gcs/utils/ActiviteUtil.java:335.
* **Activation flow (FlyFragment + gcs/utils/ActivationUtil.java):** on drone connect the app requests `PV_V_KEY_FLAG`, `PV_V_VER` (+ `PV_RC_TYPE`, `PV_V_TYPE` when the air link is up). `sysDoNotify(2)` -> read `PV_V_KEY_FLAG`; if 0 the UI blocks with an 'Activate aircraft' button and calls `getValiteKey(0)` -> `sysDoNotify(0)` -> read `PV_RO_KEY_0..15`. Pressing the button sends `activate(1)`; on `sysDoNotify(4)` the key + GPS + user id + time is stored in SharedPreferences and later uploaded with OkHttp GET to `http://api.powervision.me/app/Activation_eggActivation` (retry 3x). **The upload is fire-and-forget; the aircraft is activated purely by writing PV_V_KEY_FLAG=1 over the link.** No server response gates flight. If `PV_V_KEY_FLAG != 0`, app calls `getPSN(0)` -> `sysDoNotify(6)` -> reads `PV_RO_PSN_0..3`.
* **Wrapper flattening (native never sees these objects):** `circle(CircleParam)` -> `(x, y, z, radius, speed, isClockwise, isPause)`; `setWayPoints(WaypointParam[])` -> 8 parallel arrays `(param1[], param2[], param3[], param4[], x[], y[], z[], seq[])` (MAVLink MISSION_ITEM fields; returns -1 for empty); `setSafetyAllowedArea(SafetyAllowedAreaParam)` -> `(p1x, p1y, p1z, p2x, p2y, p2z, frame)`; `setTakeoffLand(TakeoffLandParam)` -> `(land_lat, land_lon, land_alt, status)`; `gimbalControl(GimbalControlParam)` -> `(mount_mode, stab_pitch, stab_roll, stab_yaw)`; `setPosition(PositionParam)` -> `(x, y, z, r, buttons)` (null -> -1); `startRecord(FlightRecordStartParam)` -> `(type, fileNameWithPath)`; `stopRecord(FlightRecordStopParam)` -> 13 scalars; `PowerSDKMount.mountApiLoadDevice(MountDevice)` -> `ordinal()`.
* **Wrapper bugs to be aware of:** `PowerSDK.shootStyle(int)` calls `JniNatives.shootMode`; `PowerSDKCamera.burninFw()` calls `JniNatives.takePhoto()`; `JniNatives.mountApi_sendI2cDataAckNotify` dispatches to the CAN-ack listener; `powerRayCameraStopSessionNotify` calls `startSession*` listener methods; PowerSDK getters `getPicSize/getShootMode/getShootStyle/getSDCAP` widen int->float; `requestAngularSpeed()` returns float from an int native.
* **No-fly zones are app-side only:** gcs/ui/controller/GoogleController.java:405 / GaodeMapController.java:963 read `assets` DB `newpowerdata.db` table `geodata(centerlat, centerlng, distance)` and draw red circles within 50 km; nothing is sent to the aircraft. The user 'safe area' rectangle IS sent (`setSafetyAllowedArea`) and the height limit is `GF_MAX_VER_DIST`.
* **Flight log:** `FlightRecordManager` drives native `startRecord/stopRecord` (native writes the log file); upload to `UPLOAD_FLIGHT_LOG` is app-side HTTP.
